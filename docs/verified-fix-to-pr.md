# Verified fix → GitHub draft PR

The VS Code command **Hushavyr: Create Draft PR from Verified Local Fix** publishes a patch generated by the existing **Hushavyr: Propose and Verify Local Fix** command.

Requirements: trusted local workspace, `chat.disableAIFeatures=true`, clean Git checkout, exact original verified HEAD, locally installed `git` and authenticated `gh` CLI with permission to push and create PRs. Only one workspace folder (repository root) is supported.

1. Run the existing local fix workflow. It creates `receipt.json` and `verified.patch` only if the offline red/green/suite verification succeeded.
2. Run **Hushavyr: Create Draft PR from Verified Local Fix** from the Command Palette and select that `receipt.json`.
3. The extension verifies receipt status, stages, patch SHA-256 and original commit; applies patch to a detached temporary worktree; shows the full diff including newly created regression tests.
4. Approve the separate **push and draft PR** confirmation. The extension creates a branch, commits, pushes to `origin`, and creates a **draft** GitHub PR. It never merges automatically.

No cloud LLM is used by this flow. Existing Ollama-only local verification generates the patch; the GitHub push sends the approved patch to the configured remote, so **never approve publication of private code to a public repository**. This does not run the complete test suite a second time after committing: the proof receipt must already include passing suite evidence, and CI should independently rerun tests. The active checkout is never modified.

Failure handling: on failed push/PR creation, a remote branch may remain and require manual cleanup. GitHub authentication is delegated to `gh` and Git; the extension does not handle tokens. The CLI must already be installed and logged in. This is not an autonomous background agent and does not open PRs without approval.
